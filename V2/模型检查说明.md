# 仿生眼数据集检查与纠正 V2：模型辅助质量检查

V2 保留 V1 的全部手工检查与纠正功能，新增“使用已经训练好的检测模型，找到与现有标注不一致的图片并优先复查”的流程。

## 使用步骤

1. 从上级目录运行 `./启动V2.sh`，打开需要检查的数据集。
2. 在窗口下方点击“加载模型”，选择已训练好的 Ultralytics YOLO **目标检测 `.pt`** 模型。
3. 等待模型加载。类别会按名称自动映射；名称相同但编号顺序不同也能正确对应。如果名称不同，点击“类别映射”手动指定。每个数据集类别必须对应一个模型类别，多余的模型类别可以明确忽略。加载模型不修改模型权重或标签。
4. 设置“预测置信度”，默认 `0.25`；低于该置信度的预测不会参与评分。根据需要选 CPU / GPU 0、推理图像尺寸、NMS IoU。
5. 点击“检查全部图片”。覆盖整个已打开数据集，不受当前搜索、标签状态或低分筛选的限制。进度条显示已完成数量，检查期间可以继续浏览和编辑。支持停止，已完成结果仍会保留。
6. 左侧调整“质量阈值”，默认 **80 分**，勾选“仅显示低于阈值 / 检查异常”和“按质量从低到高排序”。点击“跳到首个待复查图片”开始处理。质量阈值是严格小于，例如 80 分本身不会被 `<80` 筛选选中。
7. 选中图片后，底部显示分数、疑似原因和每个标签框的匹配得分。原标签为彩色实线，模型预测为黄色虚线，旁边显示模型类别及置信度；可关闭预测叠加。
8. 按 V1 的方式拖动/缩放、新增/删除标注框，修改类别。保存后自动用已缓存的模型预测重新比较当前标签，并更新分数、筛选状态和排序。如果需要重新运行模型，点“复查当前图片”。
9. 点击“导出质量 CSV”导出按低分排序的报告；检查结束/停止后，以及后续编辑保存时，评分结果自动保存到数据集 `.model_review/latest.json`。下次加载同一模型、映射和推理参数后，可以“载入评分结果”继续检查。质量阈值无需与上次一致。

加载模型时会读取模型元信息；开始检查时由独立进程重新加载一次模型，因此首次开始可能有等待时间。

## 质量分数怎么算

**这是一致性分数，不是标签正确率、模型准确率或置信度。** 用于优先安排人工复查，不自动判定哪一方正确。

- 仅将映射后**类别相同**的标签框和预测框配对。
- 使用一对一最大权重匹配，最大化所有配对框的 IoU 总和；一个预测框不能同时匹配多个标签框。
- IoU 是两个框的交集面积除以并集面积，越接近 1，大小位置越一致。
- 图片质量分数：

```text
分数 = 100 × 2 × 所有匹配框的 IoU 总和 / (标签框数量 + 参与检查的预测框数量)
```

| 示例 | 分数 |
|---|---:|
| 1 个标签，1 个同类别预测，框完全重合 | 100 |
| 1 个标签，1 个同类别预测，IoU=0.6 | 60 |
| 1 个标签，2 个预测，其中一个完全匹配 | 66.67 |
| 2 个标签，1 个预测，其中一个完全匹配 | 66.67 |
| 框完全重合但类别不同 | 0 |
| 有标签，模型没有检测到任何目标 | 0 |
| 空标签，模型检测到目标 | 0 |
| 空标签，模型也没有检测到目标 | 100，附“不能排除共同漏检”提示 |

缺失标签和格式异常标签记 0 分并显示原因。推理失败、图片读取失败、结果过期等**不记有效分数**，作为检查异常排到前面，不能当成高质量通过。预测框达到 300 个上限时也视为检查异常，防止用被截断的预测误评分。

每个标签框另有 `100 × 匹配 IoU` 的分数，未匹配标签框为 0。图片总分是综合得分，可能掩盖大量正确目标中的少量错误；可以同时查看单框得分并适当提高质量阈值。

## 疑似问题如何解释

- **类别不一致**：未能按同类配对，但与另一个类别预测有足够高的 IoU。
- **位置/大小偏差**：同类配对存在，但 IoU 低于“偏差提示 IoU”（默认 0.5）。
- **标签未获模型匹配**：可能是标签多标，也可能是模型漏检。
- **模型预测未获标签匹配**：可能是标签漏标，也可能是模型误检。

“偏差提示 IoU”只决定问题描述的分类界线，图片分数始终使用实际 IoU。它与模型 NMS IoU、图片质量阈值不是同一个参数。

改变质量阈值只重新筛选，无需推理。改变预测置信度、NMS IoU、推理尺寸、设备、类别映射或类别名称，会清除界面里的旧评分，需重新检查。类别重命名属于全数据集操作，推理期间暂时禁用。

## 当前环境与依赖

界面继续使用 PyQt5，可与模型推理使用不同 Python。当前默认推理解释器为：

```text
/home/ccl/miniconda3/envs/yolov11/bin/python
```

它已有 torch、ultralytics，支持 CPU 和 GPU。界面可选择其他解释器，模型加载失败时会展示错误。自定义 YOLO 层或不同训练版本的模型需要使用兼容的训练环境。

新机器可以在推理环境中安装 `requirements-model.txt`，界面环境安装 `requirements.txt`；不要求把两个环境合并。测试使用的是本机已有 `train39_best.pt`（类别为 motor_rotor / long_motor），程序不会默认替你选择模型。

## 保存与结果有效性

- 自动检查和预测叠加不修改原 YOLO 标签；手工保存仍沿用 V1 的备份和原子写入机制。
- 开始模型检查前，如果当前图片有未保存编辑，会先保存，保证检查的是磁盘上的最新标注。
- 原有图片列表中的标签状态筛选和搜索与质量筛选组合生效。取消低分筛选可重新显示所有图片。
- 标签保存后自动重新比较；当前未保存修改会明确提示评分仍基于上一次保存。
- 检查结果包括模型内容哈希、参数、类别映射、标签内容哈希和图片大小/修改时间。载入结果、打开图片或导出报告时会核对变化。标签变化可复用预测重新评分；图片变化需重新推理。
- `.model_review/latest.json` 为最新评分快照，下一次检查会更新它；需要长期保存某轮结果，可另存该文件或导出 CSV。
- 停止检查是终止推理进程，尚未返回的那张图片不算完成；未检查图片不会被当成达标图片。
- 已用这些图片训练过的模型可能学到原标注错误。模型自身也可能漏检/误检，所以请结合实物判断后纠正，不要为了得到高分机械照搬预测框。
